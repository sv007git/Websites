CORE ARCHITECTURAL CONCEPT: DUAL-MODE ENGINE
--------------------------------------------------------------------------------
The application is deliberately built with an adaptive dual-mode architecture:

1. NATIVE PHONE MODE (Hardware & Linux Subsystem):
   - When running locally on an Android phone (via Termux) or Linux PC:
   - Backend `server.js` (Node.js) serves the IDE and exposes low-overhead APIs.
   - CPU/RAM     : 100% utilizes the phone's physical multi-core ARM64 CPU & RAM.
   - Filesystem  : Real physical files on device storage (`~/antigravity-ide/workspace/`).
   - Terminal    : Spawns real `/bin/sh` or Termux `bash` child processes on the device.
                   Full access to `pkg`, `apt`, `git`, `python`, `node`, `clang`.
   - Agent Engine: Directly executes the official Google Antigravity binary
                   (`$HOME/.local/bin/agy -p "<prompt>"`) on the phone, streaming
                   autonomous reasoning, multi-file edits, and tool outputs.

2. CLOUD / STANDALONE SANDBOX MODE (Browser / GitHub Pages):
   - When visited over HTTPS (e.g. https://sv007git.github.io/IDE/) without a local
     daemon running:
   - Filesystem  : Virtual in-browser file storage (persisted in localStorage).
   - Terminal    : Built-in command emulator (`help`, `ls`, `cat`, `touch`, `rm`, `export`).
   - Code Runner : In-browser client iframe (HTML/CSS/JS) and Pyodide Wasm (Python 3).
   - Agent Engine: Direct Google Gemini API (via user API key) or built-in offline diagnostics.
   - Header Badge: Displays `🟡 Web Sandbox` with a 1-tap setup guide for native mode.

BACKEND API SPECIFICATION (server.js)
--------------------------------------------------------------------------------
Default Port: 3000 (env `PORT`). Default Host: 0.0.0.0 (env `HOST`).
Workspace Directory: `./workspace` (env `WORKSPACE_DIR`).

1. GET /api/status
   Response: {
     success: true,
     platform: "android" | "linux" | "win32",
     isAndroid: boolean,
     arch: "arm64" | "x64",
     hostname: string,
     cpuCount: number,
     cpuModel: string,
     totalMemMB: number,
     freeMemMB: number,
     agyInstalled: boolean,
     agyPath: string,
     agyVersion: string,
     workspaceDir: string,
     nodeVersion: string
   }

2. GET /api/files
   Response: {
     success: true,
     workspaceDir: string,
     files: Array<{ name: string, isDirectory: boolean, size: number, mtime: string }>
   }

3. GET /api/file/read?name=<filename>
   Response: { success: true, name: string, content: string }

4. POST /api/file/write
   Body: { name: string, content: string }
   Response: { success: true, name: string }

5. POST /api/file/delete
   Body: { name: string }
   Response: { success: true, deleted: string }

6. POST /api/file/rename
   Body: { oldName: string, newName: string }
   Response: { success: true, oldName: string, newName: string }

7. POST /api/exec
   Body: { command: string }
   Response: Streamed raw text/plain (`Transfer-Encoding: chunked`) of stdout & stderr
   executing inside `WORKSPACE_DIR` under the system shell with PATH containing `~/.local/bin`.

8. POST /api/agent
   Body: { prompt: string }
   Response: Streamed raw text/plain (`Transfer-Encoding: chunked`) of `agy -p "<prompt>"`
   running directly on the phone processor inside `WORKSPACE_DIR`.


FRONTEND GLOBAL ARCHITECTURE & SINGLETONS
--------------------------------------------------------------------------------
The client script architecture uses clean, decoupled global singletons initialized on `DOMContentLoaded`:

- `window.fs`            instance of `FileSystem` (`js/files.js`)
- `window.editorManager` instance of `EditorManager` (`js/editor.js`)
- `window.terminal`      instance of `MobileTerminal` (`js/terminal.js`)
- `window.agent`         instance of `AntigravityAgent` (`js/agent.js`)
- `window.runner`        instance of `CodeRunner` (`js/runner.js`)
- `window.auth`          instance of `AuthManager` (`js/auth.js`)
- `window.app`           instance of `AntigravityApp` (`js/app.js`)

Navigation / Panel IDs:
- `#panel-files`         Workspace file explorer
- `#panel-editor`        CodeMirror editor with mobile symbol bar
- `#panel-agent`         Antigravity AI chat panel
- `#panel-preview`       Sandboxed live HTML/CSS/JS preview
- `#panel-terminal`      Real bash terminal or sandbox emulator


ANDROID & GOOGLE ANTIGRAVITY CLI DETAILS
--------------------------------------------------------------------------------
1. Android Binary Architecture:
   - Google produces a dedicated Bionic ARM64 binary for Android (`cli_android_arm64.tar.gz`),
     stored at: `https://storage.googleapis.com/antigravity-public/antigravity-cli/.../android-arm/cli_android_arm64.tar.gz`.
   - The installer `curl -fsSL https://antigravity.google/cli/install.sh | bash` automatically
     detects `uname -o = Android` and downloads the Bionic build, avoiding glibc/musl issues.
   - The executable is installed to `$HOME/.local/bin/agy`.

2. Setup Command on Android:
   ```bash
   curl -fsSL https://raw.githubusercontent.com/sv007git/IDE/main/setup-android.sh | bash
   ```
   After setup, typing `antigravity-ide` starts the server; typing `agy` starts the TUI.

3. Authentication:
   - Antigravity CLI uses Google Device OAuth: `agy login`.
   - Opens an authorization link where the user logs into their Google account.


RULES FOR FUTURE AGENT WORK / TOKEN EFFICIENCY
--------------------------------------------------------------------------------
When prompted to make additions, bug fixes, or modifications to this project:
1. DO NOT recursively inspect or grep the entire codebase. Refer directly to the
   file map and API specifications above.

3. Editor or keyboard bar shortcuts -> edit `js/editor.js`.
4. File management or storage -> edit `js/files.js` and/or `server.js`.
5. Terminal or execution commands -> edit `js/terminal.js` and/or `server.js`.
6. Agent behavior or CLI piping -> edit `js/agent.js` and/or `server.js`.
7. Termux / Android setup flow -> edit `setup-android.sh`.
8. Always verify changes using `node -c <file.js>` before committing.
9. Always sync changes from `main` to `gh-pages`:
   `git checkout gh-pages && git merge main -m "sync" && git push origin gh-pages && git checkout main`
