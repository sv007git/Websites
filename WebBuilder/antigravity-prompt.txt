1. EXECUTIVE SUMMARY & MISSION
================================================================================
WebForge Studio is a production-grade, Mobirise-style visual website and
full-stack application development platform.

Key Capabilities:
1. Multi-Page Visual Block Assembly: 55 production blocks across 16 categories
   with drag-and-drop reordering, inline text editing, and live viewport switching
   (Desktop 1280px, Tablet 768px, Mobile 375px) with 50%-150% zoom.
2. Full-Stack Data & Schema Designer: Visual relational database builder (tables,
   fields, types, primary/foreign keys, indexes), PostgreSQL Row Level Security
   (RLS) policies, and REST API route designer.
3. 12 Complete Multi-Page Full-Stack Templates: Includes business consulting, SaaS,
   agency, portfolio, restaurant, education, blog, ecommerce, booking, CRM, ERP,
   and directory/marketplace with automated UUID-safe installation pipeline.
4. Dual Target Code Generation & Export:
   - Target A: Next.js 14 App Router + TypeScript + Tailwind CSS + Supabase (Postgres DDL with RLS).
   - Target B: Standalone PHP 8.x + MySQL/MariaDB (Clean PSR-4 MVC, PDO prepared statements, Docker).
   - Target C: Pure Static HTML/CSS.
   - Single-click ZIP package download with zero missing runtime dependencies.
5. Autonomous AI Co-Pilot: Natural language layout, theme, and database schema synthesizer.
6. Black & White (Monochrome Noir) + Cyber Slate + Clean Light Theme System.

---------------------------------------
export interface DatabaseSchema {
  tables: TableDefinition[];
  apis: ApiRouteDefinition[];
  auth: AuthConfiguration;
}

export interface TableDefinition {
  id: string;
  name: string;             // SQL table name (e.g. "users", "orders")
  displayName: string;
  description: string;
  columns: ColumnDefinition[];
  rlsPolicies: RLSPolicy[];
  seedData: Record<string, any>[];
}

export interface ColumnDefinition {
  id: string;
  name: string;
  type: 'uuid' | 'varchar' | 'text' | 'integer' | 'decimal' | 'boolean' | 'timestamp' | 'jsonb';
  isPrimary: boolean;
  isNullable: boolean;
  isUnique: boolean;
  defaultValue?: string;
  references?: { table: string; column: string; onDelete?: 'CASCADE' | 'SET NULL' | 'RESTRICT' };
}

export interface RLSPolicy {
  id: string;
  name: string;
  command: 'SELECT' | 'INSERT' | 'UPDATE' | 'DELETE' | 'ALL';
  role: 'anon' | 'authenticated' | 'admin';
  using: string;            // e.g. "auth.uid() = user_id" or "true"
  check?: string;
}

export interface ApiRouteDefinition {
  id: string;
  path: string;             // e.g. "/api/products"
  method: 'GET' | 'POST' | 'PUT' | 'DELETE';
  description: string;
  authRequired: boolean;
  targetTable?: string;
  action?: 'list' | 'get' | 'create' | 'update' | 'delete' | 'custom';
}

Template Installer Pipeline (installer.ts):
------------------------------------------
`installTemplate(template: TemplateDefinition, projectName: string, projectSlug: string): Project`
1. Deep-clones the template project.
2. Rewrites all Page IDs, Block IDs, Table IDs, Column IDs, Policy IDs, and Route IDs
   using freshly generated UUIDs.
3. Remaps internal references (e.g. Foreign Key table/column target references,
   API route target table references).
4. Sets the active project name, slug, author, and creation timestamp.
5. Emits a valid, fully editable `Project` instance.

6. EDITOR CORE & REACTIVE STATE (@webforge/editor-core)
================================================================================
State is managed via Zustand + Immer (`useEditorStore`).

Key State Properties:
---------------------
- `project: Project`: Canonical AST representation of current project.
- `activePageId: string`: ID of currently viewed page.

- `hoveredBlockId: string | null`: Currently hovered block.

8. MULTI-TARGET CODE GENERATION ENGINE (@webforge/codegen & backend-adapters)
================================================================================
The codegen pipeline compiles the AST into a virtual file map `Record<string, string>`,
which is then packaged into a `.zip` archive via `JSZip`.

Target A: Next.js 14 App Router + Supabase (PostgreSQL)
-------------------------------------------------------
Generator: `nextjs-generator.ts` + `supabase/sql-generator.ts`
Outputs:
- `package.json`: Dependencies (`next@14`, `react@18`, `@supabase/supabase-js`, `tailwindcss`).
- `tailwind.config.js`: Custom theme tokens mapped to Tailwind colors and fonts.
- `app/layout.tsx`: Root layout with font imports and metadata.
- `app/page.tsx`: Home page rendering active home page blocks.
- `app/[slug]/page.tsx`: Dynamic route rendering other project pages.
- `app/api/[...]/route.ts`: API route handlers for defined endpoints.
- `lib/supabaseClient.ts`: Supabase client initialization.
- `supabase/migrations/001_initial_schema.sql`:
  - `CREATE TABLE IF NOT EXISTS public.<name> (...);`
  - `ALTER TABLE public.<name> ENABLE ROW LEVEL SECURITY;`
  - `CREATE POLICY "<name>" ON public.<table> FOR <COMMAND> TO <role> USING (<condition>);`
  - Seed data `INSERT INTO public.<table> VALUES (...);`

Target B: Standalone Modern PHP 8.x + MySQL/MariaDB
---------------------------------------------------
Generator: `php-generator.ts` + `mysql/sql-generator.ts` + `php/code-generator.ts`
Outputs:
- `public/index.php`: Front-controller handling incoming requests and routing.
- `public/.htaccess`: URL rewrite rules routing all traffic through index.php.
- `src/Router.php`: Lightweight, zero-dependency PSR-4 regex request router.
- `src/Database.php`: PDO singleton with prepared statements and parameter binding.
- `src/Controllers/*.php`: CRUD controllers for defined tables and APIs.
- `src/Views/*.php`: Component views matching the project's block layouts.
- `database/schema.sql`: MySQL DDL with FOREIGN KEY constraints and seed data.
- `docker-compose.yml` & `Dockerfile`: Standalone container setup with Apache and PHP 8.2.

Target C: Pure Static HTML5 / CSS
---------------------------------
Generator: `static-generator.ts`
Outputs:
- Standalone HTML files for each page (`index.html`, `about.html`, etc.) with
  compiled Tailwind utility classes and zero runtime dependencies.

JSZip Packager (zip-packager.ts):
---------------------------------
`createProjectZip(project, target): Promise<Blob>`
Runs completely client-side in the browser or server-side in Node.js.

Live URL: https://sv007git.github.io/WebBuilder/

Workflow File: `.github/workflows/deploy.yml`
- Triggers on: push to `main` branch or manual `workflow_dispatch`.
- Steps:
  1. Checkout source code.
  2. Setup Node.js 20 with npm cache.
  3. `npm install`
  4. `npm test` (Runs Vitest suite - builds must pass all tests).
  5. `npm run build --workspace=@webforge/studio`
  6. Creates `apps/studio/dist/.nojekyll` and copies `index.html` to `404.html` (SPA fallback).
  7. Uses `JamesIves/github-pages-deploy-action@v4` to commit and push `apps/studio/dist`
     directly to the `gh-pages` branch.
- Why `gh-pages` branch?
  Bypasses requirement for pre-configured GitHub Pages API permissions in repository settings.
  GitHub automatically serves content from the `gh-pages` branch.

Vite Base Path Configuration:
Both `apps/studio/vite.config.ts` and `apps/preview/vite.config.ts` configure `base: './'`,
ensuring all assets use relative paths. This allows the built app to run under any sub-path
(such as `/WebBuilder/` on GitHub Pages) without asset 404 errors.

16. EXTENSION & CONTRIBUTION GUIDE FOR AGENTS
================================================================================
When adding new features, follow these exact file conventions:

To add a new Block:
1. Implement the React component in `packages/block-registry/src/blocks/<category>.tsx`.
2. Define its `BlockDefinition` (id, name, category, defaultProps, properties, render).
3. Export and register it in `packages/block-registry/src/registry.ts`.
4. It will immediately appear in the Left Sidebar Blocks panel and be editable on canvas.

To add a new Starter Template:
1. Create a `TemplateDefinition` in `packages/template-registry/src/templates/templates-partX.ts`.
2. Provide multi-page routes, blocks, theme tokens, database tables, and seed data.
3. Export it in `packages/template-registry/src/index.ts`.
4. The Template installer pipeline (`installer.ts`) will automatically support it.

To modify Code Generation:
- Next.js: edit `packages/codegen/src/targets/nextjs/nextjs-generator.ts`.
- PHP 8: edit `packages/codegen/src/targets/php/php-generator.ts` and `packages/backend-adapters/src/php/`.
- Supabase SQL: edit `packages/backend-adapters/src/supabase/sql-generator.ts`.
- MySQL: edit `packages/backend-adapters/src/mysql/sql-generator.ts`.

To customize Themes:
- Preset definitions: `packages/schema/src/theme.ts`.
- Studio UI classes: `apps/studio/src/index.css`.
- Theme selector UI: `apps/studio/src/components/shell/AppHeader.tsx` and `SettingsPanel.tsx`.
