1. EXECUTIVE SUMMARY & CORE ARCHITECTURAL MISSION
--------------------------------------------------------------------------------
The project is a dual-stack, production-ready ERP and CRM enterprise business management
suite developed on Windows. It contains two completely independent, runnable implementations
that produce identical business outcomes:

Variant A (Web Frontend + Supabase):
- Location: C:\Users\HARISH VYAS\Projects\ERP\variant-a-supabase
- Stack: React 18/19, TypeScript, Vite, Tailwind CSS, Lucide React, Supabase JS Client.

- Deployment: Hosted as a static single page application on GitHub Pages (`gh-pages` branch)
  at https://sv007git.github.io/ERP/ with source maintained on the `main` branch.

Variant B (PHP + MySQL / SQLite):
- Location: C:\Users\HARISH VYAS\Projects\ERP\variant-b-php-mysql

  (portable runtime PHP 8.5.12 bundled under `tools/php`).
- Database: Dual-driver PDO supporting MySQL 8.0+ and zero-admin SQLite 3 (`database/erp.sqlite`).
- Strict Invariants: Double-entry accounting service (sum(debit) == sum(credit)) and
  immutable stock movement ledger entries.

5. DATA DICTIONARY & RELATIONAL ENTITY SCHEMAS
--------------------------------------------------------------------------------
All tables include `organization_id` for multi-tenant isolation. Primary keys use UUIDs
or prefixed identifiers (e.g., `del-020`, `prd-020`).

Core Entities:
1. `organizations`: id, name, slug, currency (default 'USD'), created_at.
2. `users` / `user_profiles`: id, organization_id, full_name, email, role, status.
3. `leads`: id, organization_id, code (#LED0020), name, company_name, status, source, value.
4. `deals`: id, organization_id, code (#DEL0020), name, company_name, address, stage,
   probability, deal_value, status (Open/Won/Lost), priority (Low/Medium/High), due_date,
   follow_up_date, tags, projects, owners, contacts, last_modified, modified_by.
5. `deal_activities`: id, deal_id, type (activity/meeting/call/note/task/file/email),
   title, description, date_group (Today/28 Sep 2025/27 Sep 2025), priority, reminder,
   assigned_to, user_name, created_at.
6. `products`: id, organization_id, code (#PRD0020), name, sku, category, brand, unit,
   quantity, selling_price, purchase_price, reorder_level, status (In Stock/Out of Stock).
7. `stock_ledger_entries`: id, organization_id, product_id, warehouse_id, voucher_type,
   qty_change (+10 / -5), balance_after, created_at. (IMMUTABLE).
8. `warehouses`: id, organization_id, code, name, contact_person, capacity, current_utilization_pct.
9. `invoices`: id, organization_id, invoice_number (#INV0020), customer_name, invoice_date,
   total_amount, paid_amount, status (Pending/Paid/Partially Paid).
10. `payments`: id, organization_id, invoice_id, amount, payment_date, payment_method, reference_no.
11. `chart_of_accounts`: id, organization_id, code, name, type (Asset/Liability/Equity/Income/Expense).
12. `gl_entries`: id, organization_id, posting_date, account_code, account_name, debit,
    credit, voucher_type, voucher_id, remarks. (BALANCED DEBIT == CREDIT).
13. `employees`: id, organization_id, employee_code (EMP-001), full_name, email,
    department_name, position, salary, leave_balance, status.
14. `attendance_records`: id, organization_id, employee_id, date, clock_in, clock_out, status.
15. `leave_requests`: id, organization_id, employee_id, leave_type, start_date, end_date,
    days_count, reason, status (Pending/Approved/Rejected).
16. `purchase_orders`: id, organization_id, po_number (#POD0020), supplier_name, category,
    order_date, delivery_date, total_amount, ordered_qty, delivered_qty, status.
17. `projects`: id, organization_id, code (#PRO0020), name, description, progress (0-100),
    team_leader, team_members, deadline, status.
18. `tickets`: id, organization_id, code (#TKT0020), customer_name, subject, priority,
    status (Open/Pending/Resolved/Closed), assigned_to, created_at, last_updated.
19. `audit_logs`: id, organization_id, action, entity_type, entity_id, actor_id, metadata, created_at.

6. CORE BUSINESS INVARIANTS & TRANSACTION RULES
--------------------------------------------------------------------------------
1. Double-Entry Accounting Invariant:
   - For any financial posting, sum(Debit) - sum(Credit) == 0.00.
   - Enforced in `AccountingService.php` and verified by Python acceptance tests.
2. Immutable Stock Movement Ledger:
   - Physical quantities are never directly updated without an append-only row in
     `stock_ledger_entries`.
   - Disallow dispatches when current stock < dispatch quantity.
3. Atomic Leave Balance Deductions:
   - When approving leave for N days, employee `leave_balance` is decremented by exactly N.
4. Tenant Scoping:
   - Every read and write is scoped to `organization_id`. Cross-tenant data leakage is
     prevented via Supabase RLS policies and PHP SQL parameterized bindings.

8. CURRENCY CONFIGURATION & LOCALIZATION GUIDE
--------------------------------------------------------------------------------
How Currency is Designed in the System:
1. Database Level:
   - In table `organizations`, the column `currency` stores the ISO 4217 code (default: 'USD').
   - For multi-currency expansion, financial records (`invoices`, `gl_entries`, `deals`) store
     both the monetary value and reference the tenant's currency code.
2. Variant A (React / TypeScript):
   - Entity definition in `types/database.ts`:
     `export interface Organization { id: string; name: string; slug: string; currency: string; }`
   - Formatting: Currently values are formatted using `$` symbol or `deal_value.toLocaleString()`.
   - To change default currency globally in Variant A:
     1. In `src/types/database.ts` or a global formatter `src/lib/currency.ts`:
        Define `export const formatCurrency = (val: number, currency = 'USD') => ...`
        using `Intl.NumberFormat('en-US', { style: 'currency', currency })`.
     2. Update the organization record in `organizations` or `LocalErpStore` with the new code
        (e.g., 'EUR', 'GBP', 'INR', 'AED').
3. Variant B (PHP / MySQL):
   - Stored in SQLite/MySQL `organizations.currency`.
   - In `AccountingService.php` and `WebController.php`, formatted via `number_format($amount, 2)`
     prefixed by the currency symbol resolved from the tenant's profile.

10. KNOWN ISSUES, SOLVED EDGE CASES & TROUBLESHOOTING GUIDE
--------------------------------------------------------------------------------
1. Supabase Error 42501 (Row-Level Security Violation):
   - Cause: Public anon API requests cannot write to tables when policies require auth.uid().
   - Solution: Run migration `20261027000004_allow_anon_demo.sql` in Supabase SQL Editor.
   - Frontend Resilience: `LocalErpStore` uses optimistic caching in localStorage so the
     user is never blocked even if the cloud network is down or RLS is restrictive.
2. Large Reference Folders in Git:
   - Ensure `.gitignore` ignores `crm-1.89.2/`, `erpnext-16.52.1/`, `espocrm-10.0.11/`,
     `hrms-16.52.0/`, `icehrm-36.0.1/`, `idurar-erp-crm-4.1.1/`, `erpgosaas-98/`, and
     `New folder/` to avoid committing hundreds of megabytes of third-party reference sources.
3. Portable PHP on Windows:
   - Standard PHP requires VC++ runtime DLLs.
   - `tools/php/` contains portable PHP 8.5.12 along with necessary `vcruntime140.dll` and
     `vcruntime140_1.dll` files so no administrative install (`winget` or MSI) is needed.
4. Git Line Endings on Windows:
   - PowerShell commands touch files with CRLF. Run tests and git commands with standard
     Git for Windows handling.
